## 1. 策略 B 的产品合理性 —— `medium/high/review` 全部转人工，是否过度？

**结论：方向合理（风险不对称支持保守），但边界过宽，对「校园交通安全巡检」属过度保守。**

### 1.1 为什么方向是对的

- 校园交通安全的**漏报（false negative）与误报（false positive）代价严重不对称**：漏掉一次「车辆占道/人员聚集/标志缺失」，代价可能是人身伤害与学校责任；多派一次人工复核，代价只是几分钟人力。
- 因此在**证据不足**时偏保守，是安全领域的正确默认。`docs/HANDOFF.md:304-306` 也自认「82% 转人工」是**产品可用性问题、不是代码 bug**。

### 1.2 为什么边界过宽（三处证据）

**(a) 结构化下限被钉在 LLM 的「不确定率」上。**
`backend/app/services/risk.py:112-115`：

```python
if risk_level in {"medium", "high", "review"}:
    reason = f"风险等级为 {risk_level}，按校园安全复核策略需人工确认"
```

而 LLM 的 system prompt 被明确要求「信息不足时必须将 risk_level 设为 review」（`backend/app/services/llm.py:35`）。
→ **`review` 不是风险等级，是模型的「我判断不了」逃生舱。** 校园巡检的真实输入大多是「单张图片 + 有限视角」，信息不足是常态，所以 LLM 会**高频**输出 `review`。
**实测**：生产库 11 个任务里 **8 个 `risk_level=review`（73%）**（见 §3.1）。策略 B 等于把「73% 的不确定」无条件升级为「100% 转人工」。

**(b) `medium` 与 `high` 被同等处理，抹平了风险分级的意义。**
`high` 必须人工，毫无争议；但 `medium` 通常代表「存在风险但未达紧急」。把 `medium` 也一刀切转人工，等于系统**永远不自主落定任何风险等级**——产品对外承诺的「AI 研判」实际上只是「AI 提议 + 人工定级」。
**实测**：`medium` 仅 1 个任务（`cb423ff8`），说明当前样本里 medium 极少，规则主要被 `review` 触发——**再次指向 (a)**。

**(c) 82% 不降反升。** 上一轮 9/11=81.8%（`docs/HANDOFF.md:304`），本轮实测 10/11=90.9%。策略 B 并未使复核率下降。

### 1.3 分档判断

| risk_level | 策略 B 现状 | 产品建议 |
|---|---|---|
| `high` | 转人工 | ✅ 合理，保持不变 |
| `review` | 转人工 | ⚠️ 方向对，但应把它**降格为 medium + 显式不确定性**，再由分层规则决定，而不是无条件转人工 |
| `medium` | 转人工 | ❌ 过宽。建议「自动闭环 + 强制抽样复核 + 重复升级」 |
| `low` + 无理由 + 无事件 | 自动闭环 | ✅ 合理，但当前能命中者极少（9%） |

## 2. 与「替代人工」产品定位的冲突 + 自动闭环边界建议

**结论：存在真实冲突。** 若 82~91% 的任务都转人工，AI 数字员工的价值只剩「**自动检测 + 证据组装 + 报告起草 + 预筛**」，人仍然对几乎每个案件拍板——这与「替代人工巡检」的定位有实质差距。

### 2.1 建议的可执行口径（三级分流）

> 原则：**「必审集合」永远转人工（安全红线，召回率必须 100%）；「低风险常规」自动闭环；「中间地带」自动闭环但抽样审计、可升级。** 用「概率抽样」替代「全量人工」，在安全与效率之间取平衡。

- 🔴 **必须转人工（硬红线，一个都不能自动放行）**
  - `risk_level ∈ {high, review}`
  - 任何结构化**视觉事件**（人员聚集候选、逆行等，`vision_events[].requires_manual_review`）
  - 图片**无法解码**（`analyzable is False`）
  - 模型/工具/服务失败或降级
  - 明确的证据/质量/知识依据缺失理由（含「未检测到任何目标」——**举证责任在系统**，不能因拍不到就判定安全）
  - 全部检测均低于各模型可靠阈值

- 🟡 **自动闭环 + 强制抽样复核（建议新增档）**
  - `risk_level = medium` 且**无视觉事件**且图片可分析且**至少 1 个可靠检出**
  - 处置：自动闭环，但进入**抽检池**（建议抽检比例 ≥10~20%）；同一区域/点位 **7 日内重复出现 medium 自动升级为转人工**（防止「单次看起来不严重、累积成隐患」）

- 🟢 **自动闭环**
  - `risk_level = low` 且无复核理由且无视觉事件且图片可分析且至少 1 个可靠检出

### 2.2 需要注意的结构性问题（请架构师/用户一并定夺）

- **`review` 身份混淆**：项目把一个**路由状态**（要不要人看）塞进了**风险等级枚举**（`RiskLevel = Literal["low","medium","high","review"]`，`backend/app/schemas.py:8`）。建议把 `review` 从风险等级里拆出，改成「`risk_level ∈ {low,medium,high}` + `evidence_sufficient: bool`」两维字段，让**分级与路由解耦**。否则「转人工率」永远被 LLM 的不确定率绑架。
- 这属于**产品定义 + LLM 契约**的联合改动，**不应由 Codex 单方面决定**。

## 3. `general_yolo_review_conf=0.35` 未重新标定 —— 阻塞还是可延后？

### 3.1 判断依据

1. **本轮规则改动已大幅削弱该阈值的杠杆。**

   → 一个 0.34 的框**再也无法**把一张有高置信证据的图拖进复核队列。阈值现在只在「所有检测都很弱」时才生效，触发面显著变小。**本轮的工程改动在功能上部分替代了「降阈值」的收益。**

3. **不改不会造成安全隐患。** 不重标定只会让更多任务落入「全部低于阈值→转人工」分支——**偏保守方向**，不会漏报。

## 5. 转人工率验收口径 —— 可度量目标区间 / 分级标准

**结论：不建议用单一「转人工率」做唯一验收指标**，因为它会被 LLM 的「不确定率」掩盖（见 §1.2a）。建议**「一条硬红线 + 一个价值下限 + 一组分解指标」**。

### 5.1 硬红线（安全，不可协商）

- **必审集合召回率 = 100%**：`high`/`review`、任何视觉事件、无法解码、模型/工具失败、知识依据缺失——**一个都不允许被自动放行**。这是发布门禁，违反即阻断。

### 5.2 价值下限（可用性，需用户拍板阈值）

- **自动闭环率 `auto_closed_rate = 自动闭环 / 全部任务`**：
  - 说明：这是「AI 替代人工」价值能否成立的直接度量。按策略 B 现状实测 **1/11 ≈ 9.1%**（唯一闭环任务 `2c5ed069`）。
  - 建议目标：真实校园样本上**稳态 ≥ 30%**（否则数字员工对主流常规任务几乎无自主性，定位落空）。
  - **该阈值属风险偏好，必须由用户拍板**（学校能接受多大比例自动放行）。

### 5.3 分解指标（定位瓶颈，替代「一个比率」）

- **`review_rate_by_reason`（按原因分类）**：可直接复用本轮新增的 `backend/app/api/router.py:_review_reason_category`（图片质量 / 检测可信度 / 视觉事件 / 知识依据 / 风险策略 / 模型或服务）。用于回答「**复核率到底是哪一环贡献的**」。
  - 实测现状（只读）：低置信度类 6 项、人员聚集（视觉事件）4 项、图片模糊 1 项、未检出 1 项、空理由（旧症状）2 项。
- **`llm_review_uncertainty_rate = LLM 输出 risk_level=review 的比例`**：
  - 实测 **8/11 = 73%**。**这才是转人工率的结构性瓶颈**——后端的复核策略只是把它「暴露」出来，不是它产生的原因。
  - 建议目标：≤ 30%（需通过优化 prompt / 补充上游证据（多帧视频、点位台账）降低，**不是靠后端放宽策略**）。
- **抽样审计漏检率**：对「自动闭环」的任务做人工抽检，估算自动闭环的漏报率；建议 ≤1%~2%（**具体阈值需用户按风险容忍度拍板**）。这是防止「为降复核率而放过风险」的护栏。

### 5.4 分级标准（可直接作为验收用例表）

| 级别 | 触发条件 | 期望处置 |
|---|---|---|
| 🔴 必转人工 | `risk_level ∈ {high, review}`；任何视觉事件；无法解码；模型/工具失败；知识依据缺失；全部检测低于阈值 | 转人工，召回率 100% |
| 🟡 闭环+抽检 | `medium` + 无视觉事件 + 图片可分析 + 有可靠检出 | 自动闭环，进抽检池（≥10~20%），7 日内同点位复现则升级 |
| 🟢 自动闭环 | `low` + 无理由 + 无事件 + 可分析 + 有可靠检出 | 自动闭环 |
