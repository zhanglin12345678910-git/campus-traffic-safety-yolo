# 比赛演示流程

## 演示前

- 确认健康页显示数据库、Qdrant 和 YOLO26 已配置。
- 导入一份经审核的校园巡检制度或使用已明确标注的演示规范。
- 准备一张正常现场图、一张明显模糊图；避免清晰人脸与车牌。
- 不展示尚未由测试集评估证明的准确率、召回率或效率提升。

## 主链路（约 4 分钟）

1. 仪表盘说明“视觉证据 + 知识依据 + 风险研判 + 人工闭环”。
2. 新建巡检，填写校门地点并上传正常图片。
3. 任务详情实时展示 LangGraph 节点执行，而不是播放固定动画。
4. 展示原图/检测图、类别、置信度和坐标。
5. 展示命中的知识片段、风险、不确定性与整改建议。
6. 打开报告，再从历史记录返回同一任务，证明结果已持久化。
7. 若系统要求复核，执行人工确认并展示状态变化和复核记录。

## 异常链路（约 1 分钟）

上传模糊图片，展示图片质量节点转入人工复核；或者暂时移开模型文件，展示 YOLO 工具错误被记录并生成失败保护报告。强调系统没有把“未检出”解释成“现场安全”。

## 现场话术边界

系统用于巡检辅助和证据归档，不替代学校管理人员的最终判断。TT100K 是道路交通标志数据，迁移到校园场景必须通过校园样本验证；未验证类别和复杂场景不应夸大效果。
