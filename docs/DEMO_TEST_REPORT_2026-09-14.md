# 安巡智脑 · 比赛 Demo 测试报告

## 1. 测试目标与准出标准

本轮按用户最新定位验收：本地GPU版给评委演示，验证现有功能，不再改UI，不做企业级安全审计、并发/压力测试或公网部署验收。采用“范围与准入→用例/预期→执行取证→异常分类→重测→准出/交接”的通用测试流程，不宣称标准认证。

准出要求：现有图片主链路、真实云模型、知识检索、人工复核、报告、档案/反馈/统计、地图和视频分析可用；负例有可理解的拒绝或降级，无未解决的演示主链路阻断；测试不污染正式库，基本输入限制与密钥隔离通过。

## 4. 异常、根因与重测

1. 新增超限测试最初把1MB bytes作为pytest参数，自动生成超长用例ID，Windows临时目录创建失败（86 passed、2个setup errors，测试基础设施问题）。改为整数size与短ids，原数据仍在测试内生成，最终87 passed。没有修改业务逻辑以迁就测试。
2. 精简Chromium原视频预览readyState≥2并有时长，但videoWidth/Height=0，仅音轨推进；最初视频4/4的预览断言不足，不能据此宣称原画面通过。保留report.headless-first-pass.json，补真实画面尺寸/播放推进断言。
3. 相同文件正式Chrome实际2160×3840、播放时间推进、error=null；精简测试浏览器0×0。归类为该原视频在不同浏览器发行版上的解码差异，不是已证实的业务请求故障。额外只读对照1/2，明确保留失败项，不抹成全浏览器兼容。
4. 正式Chrome重新跑视频完整流程，最终结果作为本轮准出依据。此模式不调用Qwen/RAG/DeepSeek、不自动生成图片巡检归档，不把尚未实现的功能编成测试通过。

## 5. 演示边界与操作建议

- 使用本机Google Chrome及已验证的191815图、9759图、185218视频。视频源仅约4.5秒但51MB/4K60fps，分析可能等约一分钟；不要连续点击、关闭后端或把等待误当必然卡死。单次耗时不是SLA。
- 图片进入人工复核是正常安全/证据策略，不是功能失败；可向评委展示证据→确认→报告闭环，不为好看强行判低风险。
- 视频返回反向轨迹来自left_to_right配置及移动镜头，不能当真实校园逆行真值；人员聚集输出同样需现场核对。需要证明真实逆行时，应换固定机位且方向明确的素材。
- 当前测试素材里的清晰人脸/车牌公开演示前需核对授权并脱敏；人物隐私闸门只保证当前有person样例不送Qwen，不等于完整匿名化。
- 公网轻量CPU部署、Docker运行态、企业级访问权限/全浏览器兼容和负载不在本轮准出范围。以后公网展示前再完成必要访问Key/HTTPS配置；本轮不以它们阻断本地比赛Demo验收。
