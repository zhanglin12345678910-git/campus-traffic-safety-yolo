# 🚀 PSSM-YOLO-Lite 轻量化训练流程说明文档

## 📋 概述

本文档详细介绍了基于 **BN稀疏化的结构化通道剪枝** 与 **知识蒸馏** 的完整轻量化训练流程。该流程旨在显著降低 PSSM-YOLO-Lite 模型的参数量与计算量，同时尽可能保持检测性能。

### 🎯 目标

- 降低模型参数量和 GFLOPs
- 适配车载边缘平台部署
- 保持交通标志检测的精度和鲁棒性

### 📊 完整流程

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   1. 稀疏训练    │ -> │  2. 结构化剪枝   │ -> │   3. 微调训练    │ -> │  4. 蒸馏增强    │
│  train_sparse   │    │   prune_model   │    │    finetune     │    │ train_kd_after  │
│                 │    │                 │    │                 │    │     _prune      │
│ L = L_det + λΣ|γ|│    │  删除|γ|<阈值   │    │  恢复剪枝精度    │    │ L = L_det + βL_kd│
└─────────────────┘    └─────────────────┘    └─────────────────┘    └─────────────────┘
```

## 📖 各阶段详细说明

### 阶段1：稀疏训练 (`train_sparse.py`)

#### 原理

在训练损失中对所有 BN 层的缩放系数 γ 引入 L1 稀疏约束：

$$L_{sparse} = L_{det} + \lambda \cdot \sum|\gamma|$$

- $L_{det}$: 原始 YOLO 检测损失
- $\sum|\gamma|$: 所有 BN 层缩放系数的 L1 范数
- $\lambda$: 稀疏惩罚系数

当某通道对应的 |γ| 趋近于 0 时，该通道对网络激活的贡献减弱，可视为冗余通道。

#### 关键参数

| 参数 | 默认值 | 推荐范围 | 说明 |
|------|--------|----------|------|
| `sparse_lambda` | `1e-4` | `1e-5 ~ 1e-3` | 稀疏惩罚系数，值越大稀疏化越强 |
| `sparse_warmup_epochs` | `5` | `3 ~ 10` | 预热轮数，前几轮不加稀疏约束 |
| `epochs` | `100` | `80 ~ 150` | 总训练轮数 |
| `lr0` | `0.01` | `0.01` | 初始学习率 |

#### 配置示例

```python
CONFIG = {
    'model': 'yolo11-CSP-PMSFA-Lite-NoP5.yaml',
    'data': 'path/to/cctsdb.yaml',
    'epochs': 100,
    'batch': 32,
    'sparse_lambda': 1e-4,      # 中度稀疏（推荐）
    'sparse_warmup_epochs': 5,
    'project': 'runs/sparse_train',
    'name': 'PSSM-YOLO-Lite-稀疏训练',
}
```

#### 使用方法

```bash
python kd-trian/train_sparse.py
```

#### 输出

- 保存路径：`runs/sparse_train/<name>/weights/`
- `best.pt`: 验证集最优的稀疏模型
- 训练过程会打印稀疏度分析：
  ```
  [Sparsity Analysis] Total: 5120, Near-Zero: 1536, Sparsity: 30.00%, |γ| mean: 0.0234
  ```

### 阶段1.5：加强稀疏化 (`train_sparse_phase2.py`)

#### 适用场景

当第一阶段稀疏训练（100 epochs, λ=1e-4）完成后，如果稀疏度仍为0%或过低，需要用更大的 λ 继续训练。

#### 原理

- 从第一阶段的 `best.pt` 权重继续训练
- 将 `sparse_lambda` 从 1e-4 **增大到 5e-4**（5倍）
- 不需要 warmup（模型已预训练）
- 使用较低学习率保护已学特征

#### 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `sparse_lambda` | `5e-4` | 增强5倍的稀疏系数 |
| `sparse_warmup_epochs` | `0` | 无需预热 |
| `epochs` | `50` | 微调轮数 |
| `lr0` | `0.005` | 较低学习率 |

#### 使用方法

```bash
python kd-trian/train_sparse_phase2.py
```

#### 何时使用？

```
第一阶段完成后检查日志：
[Sparsity Analysis] Sparsity: 0.00%  ← 稀疏度为0，需要Phase2！
[Sparsity Analysis] Sparsity: 15.00% ← 稀疏度正常，可直接剪枝
```

### 阶段2：结构化剪枝 (`prune_model.py`)

#### 原理

1. 收集所有 BN 层的 γ 参数
2. 按 |γ| 值全局排序
3. 根据剪枝率 ρ 确定阈值
4. **使用 torch-pruning 真正删除通道和卷积核**
5. 自动处理层间依赖关系（Concat、残差等）

#### ⚠️ 重要说明

**本脚本使用 torch-pruning 进行真正的结构化剪枝：**
- ✅ 真正删除卷积核和通道（不是置零！）
- ✅ 减少模型参数量（Parameters）
- ✅ 减少计算量（GFLOPs）
- ✅ 自动处理层间依赖关系

#### 安装依赖

```bash
pip install torch-pruning
```

#### 关键参数

| 参数 | 默认值 | 推荐范围 | 说明 |
|------|--------|----------|------|
| `prune_ratio` | `0.3` | `0.2 ~ 0.5` | 剪枝率，真正删除30%的通道 |

#### 配置示例

```python
CONFIG = {
    'model': 'runs/sparse_train/PSSM-YOLO-Lite-稀疏训练/weights/best.pt',
    'prune_ratio': 0.3,
    'save_dir': 'runs/pruned/PSSM-YOLO-Lite-结构化剪枝',
}
```

#### 使用方法

```bash

```

#### 输出

- 保存路径：`runs/pruned/<name>/`
- `pruned_model.pt`: 剪枝后的模型（参数量和计算量真正减少！）

### 阶段3：微调训练 (`finetune.py`)

#### 原理

使用较小的学习率对剪枝后的模型进行再训练，恢复因剪枝造成的精度损失。

#### 微调策略

1. **学习率**：使用较小的初始学习率（0.001-0.01）
2. **数据增强**：适当减少增强强度
3. **训练轮数**：比完整训练少（30-100轮）
4. **冻结层**：可选择冻结部分层

#### 关键参数

| 参数 | 默认值 | 推荐范围 | 说明 |
|------|--------|----------|------|
| `epochs` | `50` | `30 ~ 100` | 微调轮数 |
| `lr0` | `0.001` | `0.001 ~ 0.01` | 初始学习率（比正常训练小） |
| `warmup_epochs` | `3` | `1 ~ 5` | 预热轮数 |
| `freeze` | `None` | `None` 或 `10` | 冻结前N层 |

#### 配置示例

```python
CONFIG = {
    'model': 'runs/pruned/PSSM-YOLO-Lite-剪枝/pruned_model.pt',
    'data': 'path/to/cctsdb.yaml',
    'epochs': 50,
    'lr0': 0.001,
    'freeze': None,
    'project': 'runs/finetune',
    'name': 'PSSM-YOLO-Lite-微调',
}
```

#### 使用方法

### 阶段4：蒸馏增强 (`train_kd_after_prune.py`)

#### 原理

以高精度 PSSM-YOLO 作为教师模型，对剪枝后的轻量化模型进行知识蒸馏：

$$L_{total} = L_{det} + \beta \cdot L_{kd}$$

蒸馏损失定义：

$$p_t = \text{softmax}(z_t / T)$$
$$p_s = \text{softmax}(z_s / T)$$
$$L_{kd} = T^2 \cdot \text{KL}(p_t \| p_s)$$

- $z_t, z_s$: 教师/学生的分类 logits
- $T$: 蒸馏温度
- $\beta$: 蒸馏损失权重

#### 教师-学生检测头不同的处理

| 模型 | 检测头数量 | 检测尺度 |
|------|------------|----------|
| 学生模型 (NoP5) | 3 | P2, P3, P4 |
| 教师模型 | 4 | P2, P3, P4, P5 |

**处理方式**：代码会自动对齐，仅对共同尺度 (P2, P3, P4) 进行蒸馏。

#### 关键参数

| 参数 | 默认值 | 推荐范围 | 说明 |
|------|--------|----------|------|
| `kd_temp` | `4.0` | `2 ~ 6` | 蒸馏温度 T |
| `kd_weight` | `1.0` | `0.5 ~ 2.0` | 蒸馏损失权重 β |
| `epochs` | `50` | `30 ~ 100` | 蒸馏轮数 |
| `lr0` | `0.005` | `0.001 ~ 0.01` | 初始学习率 |

#### 温度 T 的影响

| 温度 | 效果 | 适用场景 |
|------|------|----------|
| T=2-3 | 保留更多判别性 | 类别区分度高的数据集 |
| T=4-5 | 平衡性能 | **推荐首选** |
| T=6+ | 蒸馏效果更柔和 | 教师模型过拟合时 |

#### 配置示例

```python

    'student': 'runs/finetune/PSSM-YOLO-Lite-微调/weights/best.pt',
    'teacher': 'path/to/PSSM-YOLO/best.pt',
    'data': 'path/to/cctsdb.yaml',
    'epochs': 50,
    'kd_temp': 4.0,
    'kd_weight': 1.0,

```

## 🚀 一键执行完整流程 (`run_pipeline.py`)

### 功能

整合全部四个阶段，一键执行完整的轻量化流程。

### 配置

```python
PIPELINE_CONFIG = {
    # 基础配置
    'student_model': 'yolo11-CSP-PMSFA-Lite-NoP5.yaml',
    'teacher_model': 'path/to/teacher/best.pt',
    'data': 'path/to/cctsdb.yaml',
    
    # 阶段控制（enabled: True/False）
    'sparse': {'enabled': True, 'epochs': 100, 'sparse_lambda': 1e-4, ...},
    'prune': {'enabled': True, 'prune_ratio': 0.3, ...},
    'finetune': {'enabled': True, 'epochs': 50, ...},
    'distill': {'enabled': True, 'epochs': 50, 'kd_temp': 4.0, ...},
}
```

### 使用方法

```bash
python kd-trian/run_pipeline.py
```

### 灵活执行

通过设置 `enabled: False` 可跳过某些阶段：

| 场景 | 配置 |
|------|------|
| 只做稀疏训练 | prune/finetune/distill 设为 False |
| 跳过稀疏直接剪枝 | 需手动指定预训练模型 |
| 只做蒸馏 | sparse/prune/finetune 设为 False |

### 输出目录结构


## ⚠️ 常见问题

### Q1: 稀疏训练后精度下降很多？

**原因**：λ 值过大导致过度稀疏化

**解决**：
- 减小 `sparse_lambda` (如 1e-5)
- 增加 `sparse_warmup_epochs`

### Q2: 剪枝后模型无法加载？

**原因**：结构化剪枝改变了模型结构

**解决**：
- 使用软剪枝 (`use_soft_prune=True`)
- 或使用 torch-pruning 的专用加载方式

### Q3: 教师-学生检测头数量不同报错？

**原因**：学生模型 (NoP5) 只有 3 个检测头

**解决**：代码已自动处理，仅对共同尺度蒸馏。若仍报错，检查日志中的维度匹配信息。

### Q4: 蒸馏效果不明显？

**尝试**：
- 增大 `kd_weight` (如 1.5-2.0)
- 调整温度 T (尝试 T=2 或 T=6)
- 增加蒸馏训练轮数

### Q5: GPU 显存不足？

**解决**：
- 减小 `batch` 大小
- 减小 `imgsz` (如 512)
- 使用梯度累积
