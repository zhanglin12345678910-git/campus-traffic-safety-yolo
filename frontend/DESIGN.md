# 安巡智脑前端设计规范 v7

> 当前方向：真实数据驱动的精密科技感 GIS 校园安防指挥台（2026-09-13 六张参考图实施版）。
> 适用范围：`frontend/` 内全部 Vue 页面与 Element Plus 组件。
> 本文件是前端视觉和布局的唯一事实来源；v2 的“深色玻璃大 Hero”和 v3 的普通数据卡工作台均已废弃。

视觉真值由用户选定的“GIS 安巡作战台”截图及 2026-09-13 生成的六张系统参考图共同构成：深灰黑画布、窄顶栏、四项横向态势指标、校园地图主视图、右侧风险事件队列、底部巡检与检测表格，以及同一语言下的分析、视频、知识库、设置和复核工作台。参考图中的数字与事件仅用于构图，不是业务数据；实现必须接入现有后端，不能照抄参考图数据。

## 1. 产品气质

界面首先是一套需要快速判断、快速处置的工作台，不是宣传页。视觉目标是：

- 一屏内优先呈现状态、风险、任务和下一步操作。
- 使用稳重的深灰蓝实色分层，不依赖大面积玻璃、光晕或渐变。
- 用少量蓝色指出当前导航和主操作；红、黄、绿、紫只表达业务状态。
- 文字、数据、表格和表单是主角，装饰必须让位于信息。

布局参考成熟后台的通用结构，不直接引入其他框架代码：

- [Grafana Dashboard Best Practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/)：状态优先、面板标题明确、关键指标集中。
- [Tabler Admin Template](https://tabler.io/admin-template)：紧凑侧栏、实色卡片和响应式后台骨架。Tabler 源码为 MIT 许可。
- [shadcn Dashboard Example](https://ui.shadcn.com/examples/dashboard)：指标卡、图表、表格和快捷操作的组合关系。

## 3. 布局规则

### 应用骨架

- 桌面侧栏宽 `216px`，折叠后 `76px`。
- 顶栏高 `56px`，呈现天气、日期、时间、系统状态、消息和当前值班员。天气只取高德实况天气接口 `/api/v1/maps/weather`（`campusProfile.adcode`），不可用时隐藏，禁止写死温度或天气文字。
- Dashboard 贴边铺满工作区，区域间距 `12px`；其他业务页内容边距 `22px`。
- `1081px` 及以上桌面端 Dashboard 必须按视口高度分配“指标区 + 主区”，GIS、事件队列和底部表格共同铺满首屏，不保留无意义的底部空白。
- 卡片和面板圆角以 `7–9px` 为主，输入框圆角 `4px`，依靠边框而不是大阴影分层。
- 1492×1072 基准视口下，地图区约占主内容宽度的四分之三、风险事件队列约 `342px`。

### 信息顺序

工作台页面遵循以下顺序：

1. 页面标题、用途说明和一个主操作。
2. 关键数字或当前状态。
3. 主任务区，例如表格、图片或复核队列。
4. 次要信息，例如风险构成、执行链路或帮助说明。

禁止重新加入占据首屏的大 Hero。页面标题区建议高度 `60–80px`，不使用背景卡片。

### 空状态

- 空状态说明“为什么为空”和“下一步做什么”。
- 后端未启动时显示接口错误；后端没有记录时显示真实空状态。禁止用内置数组、随机数、参考图数字或演示任务替代后端响应。
- 空状态不得进入详情、执行或人工确认流程；训练目标值、冒烟指标和参考图占位值不得作为业务数据展示。
- 不再使用巨型空白面板作为默认展示。

## 4. 排版

- 中文沿用第2节的 `--font-ui / --font-display` 字体链，首选当前已安装的 `Noto Sans SC`；不得恢复旧的PingFang首选说明。
- 页面标题 `28–34px / 700`（移动端25px），卡片标题 `15–18px / 600–700`，正文 `12–14px`，完整风险摘要14px常规字重。
- 指标数字 `29px / 600`，使用等宽字体与 `tabular-nums`。
- 字重只使用 400、500、600、700；正文不使用大面积纯白。
- 英文眉标仅作为小号分类标签，不重复中文标题，不得成为视觉主体。

## 5. 核心组件

### 导航

- 当前项使用 `#182237` 背景、蓝色左边线和浅蓝图标。
- 菜单采用真实图标库，不使用编号、emoji 或手绘 SVG。
- 菜单路由在 `src/router.ts`，菜单项在 `src/components/AppLayout.vue`，改名或增删时必须同步。
- 侧栏底部展示智能体整体状态，不展示未经接口支持的数量。
- “人工复核”角标和顶栏消息数只取 `/dashboard` 的 `review_required`；接口不可用或为 0 时不显示角标。

### 卡片

- 普通卡片：`--panel` 实色背景、`1px --line-soft` 边框、无玻璃模糊。
- 卡片内边距通常 `18px`，同组内容间距 `6–12px`。
- 阴影只用于浮层和主按钮；普通卡片依赖边框与亮度分层。
- 禁止卡片套卡片超过两层。

### 指标卡

- 每张卡只回答一个问题：名称、数值、业务解释。
- 图标放在右上角 28px 色块中。
- 状态色只用于底部细线、小徽章或图标，不铺满整张卡。
- 百分比单位小于主数字。

### 表格与列表

- 表头高约 `39px`，数据行高约 `46px`。
- 行可点击时必须有 hover 反馈并保持鼠标指针。
- 风险、状态使用紧凑徽章；时间、编号和耗时优先等宽数字。
- 移动端有数据时允许横向滚动，不压缩成不可读的窄列。

### 表单与上传

- 桌面端表单与图片上传并排；移动端转单列。
- 必填字段在视觉和校验文案中同时表达。
- 上传区保持清楚的边界、格式限制和隐私提醒。
- 主要提交按钮在上传区底部，宽度与上传区一致。

### 图表

- 业务图表只呈现真实接口数据；接口无数据时显示空状态，不生成离线演示火花线。
- 图表使用 ECharts，不用 CSS 形状伪造数据可视化。
- 风险颜色固定：高风险红、中风险黄、待复核紫、低风险绿。
- 图表必须在容器尺寸稳定后初始化，并监听窗口变化。
- 复杂页面使用 `DataChart.vue` 统一承载 ECharts 生命周期、尺寸监听、空状态和无障碍名称；页面只负责准备 option 与业务解释。
- 每张分析卡必须同时给出“图表标题 + 统计口径/范围 + 一句可行动解释”，禁止只画图不解释，也禁止为填充空间重复同一指标。

## 6. 页面规范

### 态势总览

- 首行四项横向指标：今日巡检、待复核、高风险事件、在线摄像头；每项含真实图标、数值、变化文本和 ECharts 火花线。
  - 真实模式：今日巡检取 `today_tasks`，变化文本为与昨日的差值；待复核取 `review_required`；高风险取 `risk_counts.high`；三条火花线取 `daily_trend` 近 7 日数据。后端缺少这些字段时显示“—”和“后端未提供趋势数据”，不得用 0 冒充。
  - 没有接口支撑的指标（当前为在线摄像头）在真实模式显示“—”和“摄像头接口未接入”，不画火花线。
- 主区以校园 GIS 地图为绝对视觉主角；地图包含真实栅格底图、风险点位、摄像头、门岗、地标文字、图层切换和缩放/复位控件。
  - 当前真实任务没有地图坐标，项目也没有摄像头接口，因此风险点位、摄像头和重点区域图层均置灰（`is-disabled`）；接口补齐前不得绘制模拟点位。
  - 地标文字与门岗是按参考图写死的百分比坐标，尚未按真实高德底图校准（见 `docs/HANDOFF.md` 待办）。
- 当前校园地理基准为四川现代职业学院：国内地图默认中心使用 GCJ-02 `[103.997424, 30.515862]`，GeoJSON/OSM 备用中心使用 WGS84 `[103.995133, 30.518507]`；坐标顺序统一为 `[经度, 纬度]`。
- 右侧固定为风险事件队列，包含风险等级、地点、时间、置信度与真实道路图片。
  - 风险等级按接口原值显示：高风险、中风险、低风险、待复核（紫色）、未研判（灰色），不得把 `review` 或空值折算成中/低风险。
  - 置信度取任务的 `max_confidence`；没有检测结果时显示“—”。
- 地图下方并排显示巡检任务和 AI 近期检测，保持参考图中的高信息密度。
  - 真实模式的处置状态取任务 `status`；巡检进度只区分“流程已结束 100% / 未开始 0% / 执行中 —”，不编造百分比；负责人为空时显示“未填写”。
- `/dashboard` 只映射真实任务；无数据时显示空状态，不可用时显示接口错误。

### 数据分析

- `/analytics` 是 Dashboard 的纵向分析补充，不替代 GIS 态势页；它回答“风险在哪里、为什么转人工、模型识别了什么、系统慢在哪个节点”。
- 首行固定展示累计巡检、闭环完成率、人工复核率和平均链路耗时，数据来自 `/api/v1/analytics/overview`。
- 主区使用 12 列响应式网格：30 日趋势与风险构成同排，区域分布与复核原因同排，双模型贡献、高频类别、Agent 节点耗时三卡同排；1080px 以下两列，780px 以下单列。
- 双模型贡献按 `model_role + model_name` 分组，同时展示检出数量和平均置信度；历史记录中旧的 `yolo26n.pt` 与当前 `yolo26m.pt` 必须如实分开，不得改写历史模型名称。
- 复核原因按任务内类别去重后统计，防止同一任务中同类提示重复放大；空库时显示原因和下一步，不注入演示任务。
- 图表配色、边框、圆角和字体沿用 GIS 指挥台令牌；不得引入另一套模板主题或在页面内散落新色值。

### 新建巡检

- 标题区说明完整流程。
- 左侧填写地点、区域、现场说明和人员；右侧上传图片并提交。
- 表单工作区右侧固定为提交准备度、智能体执行链和当前识别范围；这些内容必须随表单模式与输入状态变化，不能用装饰性占位填充。
- “最近真实巡检”必须放在主操作列内部并紧跟表单/上传区，不能放在整个左右网格之后；否则右侧说明栏较高时会在主列下方制造大段空白。
- 智能体边界与个人信息提示保留。

### 巡检档案与人工复核

- 筛选项靠近列表标题，不单独占一行。
- 复核原因使用紫色业务标签。
- 档案页右侧展示真实闭环率、状态分布和区域覆盖；复核页右侧展示真实队列构成、标准复核流程和人工判定原则。
- 空队列保持紧凑，不渲染巨型空白面板。

### 知识库与设置

- 知识文档、检索测试和知识治理侧栏在宽屏同排；设置页使用服务状态、密钥说明和运行链路三栏工作台。
- 所有统计从当前接口数据派生，不使用写死数量填充页面。
- API Key 说明必须明确“仅当前浏览器标签页”。

### 巡检详情

- 任务身份和操作固定在最上方。
- 首层使用“原图/识别图 + 右侧风险、知识、不确定性、模型来源”，第二层使用可横向浏览的 Agent 执行轨迹与结构化检测表；小屏转单列。
- Agent 全部真实节点必须保留，但重复执行产生大量节点时不得纵向撑出巨型空洞，使用横向证据窗浏览。
- 风险摘要、整改建议和知识依据均来自任务详情接口；知识引用只在右侧证据栏展示一次，避免重复长正文破坏页面高度。
- 原图与结果图必须保持完整比例，不裁切证据。

## 7. 响应式

### `1081px` 及以上

- 使用完整固定侧栏和顶栏。
- 侧栏底部展示校园建筑线稿与“厚德 精技 / 笃行 创新”校训，作为品牌识别装饰；它不承载任何实时业务含义，折叠侧栏与移动端隐藏。
- Dashboard 四列指标、地图主区和右侧事件队列同屏展示。
- 业务页面使用 `width: 100%` 的流式工作区，主任务区配 260–280px 上下文侧栏，不设置导致空卡片的视口强制最小高度。

### `781–1080px`

- 侧栏收窄为图标栏，事件队列移动到地图下方。
- 四项指标保持两列。

### `780px` 及以下

- 主导航固定到底部，顶栏保留天气、时间、系统状态、全屏和消息入口。
- 指标卡保持两列，避免滚动过长。
- 地图、任务表、检测表和事件队列纵向排列；巡检档案由宽表格切换为移动卡片，禁止撑宽文档视口。
- 表单、详情、知识库全部单列。
- 触摸目标尽量不低于 `40px`。

## 8. Element Plus 约定

- `main.ts` 中 `element-plus/dist/index.css` 必须在 `styles.css` 前引入。
- 所有深色 `--el-*` 色阶必须与 `#121923` 附近的深色表面混合，禁止使用浅色默认色阶。
- 弹窗、消息、下拉框和加载遮罩必须进行真实页面检查。
- 不依赖 `.el-*` 内部结构实现业务逻辑，只做视觉覆盖。

## 9. 实施与验收

每次视觉改动至少执行：

1. `npm run build`，其中 `vue-tsc -b` 必须零错误。
2. 真实浏览器检查 1440×1000 的 Dashboard、数据分析、巡检表单、档案、复核、知识库和设置页。
3. 检查 390×844 的 Dashboard、数据分析、巡检表单和至少一个双栏页面。
4. 检查浏览器控制台；业务接口异常必须与纯静态资源错误区分。
5. 不改现有 API、路由语义和业务流程，视觉改造不得绕过后端验证。

## 10. 禁止事项

- 禁止重新加入大 Hero、全屏光晕、重度玻璃拟态或装饰性巨大标题。
- 禁止使用 emoji、文本符号或手绘 SVG 代替界面图标。
- 禁止把未标注的示例数据伪装成实时监控数据。
- 禁止为了“显得丰富”增加无功能按钮。
- 禁止普通卡片使用强阴影、彩色渐变或超过 `12px` 圆角。
- 禁止移动端把表格列硬挤到无法阅读。
- 禁止顺手修改后端业务逻辑。

## 11. v5 视觉收口

- 顶栏与侧栏使用最深表面，内容面板使用亮一级墨蓝色与顶部细高光；主指标独立成卡，数字优先。
- 图表沿用真实 ECharts 数据，取消默认斜线/圆点纹理，保留文字标签、图例和 ARIA；图例/坐标字为 12px，分析页配色读取全局 token。
- 分析页增加待复核提示带及真实队列入口；不修改统计口径、历史数据、风险判定与接口。
- 地图只调整展示滤镜，现场证据缩略图去掉压暗处理；地图点位正确性属于后续独立审核，不能从视觉通过推断地理正确。
- 系统减弱动态效果偏好启用时，取消 CSS 过渡；手机端保留两列指标及单列图表，导航固定底部。

- 六张参考图位于 `design-references/generated-2026-09-13/`，覆盖态势总览、巡检创建/视频、数据分析、人工复核详情、知识库和系统设置；它们只约束布局、密度、层级与视觉语言。
